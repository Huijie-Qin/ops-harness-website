# ADR 0024：用户选择正式版或 Beta / RC 更新

状态：接受。2026-10-08 用户要求官网与 Desktop 同步实现更新频道选择。

`GET /api/releases/check` 增加可选参数 `channel=stable|beta`。新版 Desktop 始终发送用户保存的选择：`stable` 只接受更高正式版，`beta` 接受更高正式版及 SemVer 预发布首段精确为 `beta` 或 `rc` 的版本，排除 `alpha`、`dev` 和其他预发布类别。关闭测试版后不降级；已安装 Beta / RC 的用户等待更高正式版。

用户确认现有用户全部使用正式版，未传 `channel` 统一按 `stable` 处理，仅接收更高正式版；删除按当前安装版本推断渠道的分支。旧三参数请求继续有效，即使手动安装旧预览客户端，也只接收更高正式版。新版客户端不在请求失败后去掉用户选择重试。官网先升级、新客户端后发布。

频道类型和允许规则只在产品仓库的 `@dsh-ops/release-contract` 维护。官网与 Desktop 共用精确版本 0.1.3 制品；公开消息 `schemaVersion` 保持 1，响应、发布 catalog 与固定版本 feed 形状不变。官网继续拒绝未知、重复及无效请求参数。

频道仅增加候选过滤；版本排序、平台、启用状态、发布时间、最低版本和灰度规则保持不变。灰度输入不增加频道，不改变同实例对同版本的平台分组。官网更新页仍公开所有已启用且已到发布时间的版本，允许手动下载；首页默认下载仍只提供正式版。

公开更新页和管理员草稿、版本详情显示“正式版 / Beta 测试版 / RC 候选版 / 其他预览版”。管理员发布确认说明新客户端的受众与旧客户端兼容行为；其他预览版明确提示不会进入新版客户端自动更新。类别由版本派生，不新增可人工改写的发布字段。

发布仍复用 `latest.yml` / `latest-mac.yml` 和 `archive/<完整版本>/<平台>/` 不可覆盖归档。文件匹配改为完整版本加实际平台/portable 尾缀并锚定扩展名末尾，避免将 `0.3.0-beta.1` 包误登记为 `0.3.0`，保留无架构尾缀的 NSIS EXE、Windows portable ZIP、macOS arm64 ZIP/DMG 和 blockmap 命名。

验证覆盖新旧请求、频道分类、客户端二次校验一致性、灰度及最低版本、无降级、Manifest / CLI 完整版本匹配、不可覆盖归档、制品来源与两仓库集成。浏览器检查公开列表、后台导入与受众确认、键盘/Escape、窄屏、Console/Network。Windows 真实下载 smoke 与签名安装升级仍在目标平台执行。
