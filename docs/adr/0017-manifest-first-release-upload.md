# ADR 0017：先导入构建描述文件，再校验发布包上传

- 状态：接受（2026-09-15，用户要求补充上传完整性校验并自动提取版本）。
- 替代 ADR 0013 中网页手动填写版本、首次接收哈希作为基准的流程。公开更新协议、CLI 与不可覆盖归档保持兼容。

## 问题与行为

原网页上传在服务端计算首次收到的字节哈希，只能防止该次接收之后的变化，无法与打包机器上的文件核对。新建发布先选择 electron-builder 输出的更新 YAML（通常为 `latest.yml` / `latest-mac.yml`），服务端从 `version` 与 `files[]` 提取版本、平台和每个文件的名称、大小、SHA-512。用户只填写标题及更新说明，保存草稿后才能上传对应软件包。

描述文件预览接口不写入状态。创建草稿时重新解析原始 YAML，不信任浏览器传入的解析结果。保存后锁定版本、平台和校验清单；需要更换构建时新建草稿。原始文件名与 YAML 内容存于 `draft.json` 的 `manifest` 中，读取时从原文派生清单，避免两份可独立修改的校验数据。

## 接收与发布

软件包只能使用清单中的完整原文件名。服务端边接收边写临时文件并计算 SHA-512，接收完成后比对实际大小与清单哈希，通过才 rename 并更新草稿 revision；不一致时移除临时文件，草稿和 revision 不变。网络中断、超时和取消继续清理部分上传。

主更新文件必需：Windows x64 为唯一 EXE，macOS arm64 为唯一 ZIP。清单中其他匹配平台的文件可选，所有实际上传的文件均须匹配清单。未列出的附件不允许从网页上传。发布时检查草稿清单，再将文件复制到临时归档，重新读取、计算哈希，与原描述文件中的对应条目核对；复用发布互斥锁、不可覆盖归档与原子 catalog 提交。公开的 latest YAML 仍从已验证的 catalog 生成，不直接对外提供用户上传的原始 YAML。

旧草稿没有 manifest 时仍可读取、维护说明和移除文件，但不能继续上传或发布。补充描述文件必须携带最新 revision、匹配旧草稿版本与平台；已有文件的记录和实际磁盘字节都通过比对后才能提交。已发布版本的维护无需补充描述文件。

## 输入边界

只在现有管理员会话、Host/Origin、CSRF 保护内开放 JSON 接口：`POST /api/admin/releases/manifest` 预览，`POST /api/admin/releases` 创建，`PUT /api/admin/releases/drafts/:id/manifest` 补充旧草稿。沿用 JSON 体积和接收超时限制；原 YAML 限制 32 KiB、8 个文件、有限节点与嵌套深度。拒绝多文档、重复键、标签、锚点与别名、无效版本/文件名/大小/哈希、重复文件、歧义平台和 Web installer packages。使用已锁定的 yaml 包和 vendor 的版本/文件/哈希契约，无新依赖，也不修改共享制品。

只接受本地文件名或其 URL 编码形式；拒绝路径、远程 URL 和路径穿越，绝不读取 YAML 指向的本地文件或远程资源。旧格式顶层 path/sha512 若存在，必须成对且与 files[] 一致。非升级用途的其他普通元数据可忽略，不参与权限、地址或发布策略。

此处验证字节完整性，不验证 EXE 内部结构、Authenticode 或安装效果。描述文件须来自原始构建；攻击者若同时控制包和描述文件，哈希不能证明来源可信。CLI 保留原有本地发布行为，不要求描述文件。Windows 真实安装升级验收仍在目标平台执行。

## 验证

覆盖合法 Windows/macOS 描述文件、编码文件名、预发布版本、恶意 YAML、缺失大小/哈希、同大小字节变化、截断和追加、取消清理、校验失败后重试、旧草稿补充与过期 revision、发布前磁盘内容变化、清单持久化、公开 feed 哈希一致，以及管理员鉴权边界。UI 在隔离存储中验收文件导入、自动版本、上传失败/重试、发布确认、键盘与 Escape、窄屏和页面切换。
